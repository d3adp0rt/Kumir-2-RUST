# Что перенесено из КуМир 2 в Rust

Документ фиксирует состав переноса: какие компоненты оригинала
реализованы, где они находятся в этом репозитории, что изменено и что пока
не перенесено. Оригинал: `kumir-source` (КуМир 2, Qt/C++, GPLv3).

## 2. Язык: что поддерживается

### Лексика

* русские и английские ключевые слова (`russian.keywords`,
  `english.keywords`); язык определяется автоматически по наличию
  кириллицы в файле;
* комментарии `|`, `!`, `#`, `//`;
* строки и символы в одинарных и двойных кавычках;
* целые, вещественные, экспоненциальная форма (`1e-3`, `1е-3`),
  шестнадцатеричные `$FF`;
* операторы `:=`, `+ - * / **`, `= <> < > <= >=`, `≤ ≥ ≠`;
* знак `нс` как литерал новой строки.

### Синтаксис

* главный алгоритм — первый алгоритм файла (как в КуМир 2), независимо от
  наличия имени;
* алгоритмы с возвращаемым типом (`алг цел F(...)`), `знач := …`;
* параметры `арг`, `рез`, `аргрез`, запись `арг рез` с пробелом;
* имена алгоритмов, переменных и параметров из нескольких слов
  (`алг Сумма чисел`, `цел число проходов`);
* объявления в любом месте тела, смена типа в списке
  (`файл f, вещ x, y`);
* массивы `целтаб A[1:N, 1:M]`, `цел таб`, инициализация `{…}`;
* `если … то … [иначе …] все`;
* `выбор … при … : … иначе … все`, двоеточие необязательно;
* циклы `нц для … от … до … шаг …`, `нц пока`, `нц N раз`,
  `нц … кц`, `нц … кц при …`, `кц_при`;
* `выход` (из цикла или алгоритма), `утв`, `пауза`, `стоп`;
* `ввод`/`вывод`, в том числе с файлом в качестве первого аргумента;
* форматирование `вывод x:ширина:знаков`;
* `использовать <модуль>` и `использовать "файл.kum"`;
* `ВКЛЮЧИТЬ "файл"` (текстовая вставка);
* `модуль … кон_исп` / `module … end_module` (содержимое обрабатывается
  как часть программы).

### Семантика

* массивы и строки индексируются от 1;
* `div` — деление с округлением вниз, `mod` — неотрицательный остаток
  (как в оригинале);
* `int(x)` — округление вниз (а не к нулю);
* `/` всегда даёт вещественное значение;
* `**` для целых неотрицательных степеней даёт целое;
* массивы — значения (присваивание и `арг`-параметры копируют);
* `рез`/`аргрез` — ссылки на переменную или элемент массива вызывающего;
* выход за границы массива/строки, деление на ноль, неинициализированная
  переменная — ошибки выполнения с номером строки;
* вывод вещественных по правилам оригинала (до 13 значащих цифр,
  экспонента при |x| < 10⁻⁴ или ≥ 10⁶, удаление хвостовых нулей);
* логические значения выводятся как `да`/`нет`.

### Стандартная библиотека

Перенесены все функции из `stdlibmodules.h`:

* RTL: `abs`, `arccos`, `arcctg`, `arcsin`, `arctg`, `cos`, `ctg`,
  `ждать`, `div`, `exp`, `iabs`, `imax`, `imin`, `int`, `irand`, `irnd`,
  `lg`, `ln`, `max`, `min`, `mod`, `rand`, `rnd`, `sign`, `sin`, `sqrt`,
  `tg`, `МАКСВЕЩ`, `МАКСЦЕЛ`, `вещ_в_лит`, `время`, `длин`, `код`,
  `лит_в_вещ`, `лит_в_цел`, `символ`, `юнисимвол`, `цел_в_лит`, `юникод`,
  `Цел`, `Вещ`, `Лог`, `@поставить оценку`, `НАЗНАЧИТЬ ВВОД/ВЫВОД`;
* Файлы: `открыть на чтение/запись/добавление`, `закрыть`,
  `начать чтение`, `конец файла`, `установить кодировку`,
  `можно открыть на чтение/запись`, `есть данные`, `существует`,
  `является каталогом`, `создать каталог`, `создать файл`, `полный путь`,
  `удалить_файл`, `РАБОЧИЙ КАТАЛОГ`, `КАТАЛОГ ПРОГРАММЫ`,
  `удалить_каталог`, `консоль`;
* Строки: `верхний регистр`, `нижний регистр`, `позиция`, `позиция после`,
  `поз`, `поз после`, `вставить`, `заменить`, `удалить`.

Дополнительно принимаются английские имена из `english.keywords`
(`read open`, `eof`, `uppercase`, …) и устаревшие варианты вроде
`создать файл`.

## 3. Формат `.kum` и совместимость

Реализация в `kumfile.rs` повторяет `KumFileHandler`:

* строка с `|@hidden` в конце — скрытая (учительская) строка;
* строка с `|@protected` — защищённая строка видимой части;
* `|@signature <base64>|@hidden` — подпись скрытого текста;
* при компиляции скрытый текст добавляется к видимому (как в оригинале);
* при сохранении маркеры восстанавливаются на своих местах.

Отличия:

* ведущие пробелы **не удаляются** при чтении (оригинал нормализовал
  отступы); это лучше для редактора и не влияет на компиляцию;
* подпись сохраняется, но криптографическая проверка/генерация ключей
  (QtCrypto/QCA) не реализована — поле просто переносится;
* защищённые строки подсвечиваются, но редактор не блокирует их изменение;
* файлы читаются как UTF-8 (с BOM или без) или Windows-1251; запись — UTF-8,
  BOM сохраняется, если он был.

### Пользовательские модули

`использовать "stack_calk.kum"` и `использовать Имя` (файл `Имя.kum` в
каталоге программы) загружают модуль рекурсивно. Его глобальные величины,
инициализатор и алгоритмы добавляются в программу. Встроенные модули
(`Файлы`, `Строки`, `Робот`, `Черепаха`, `Чертежник`, …) не ищутся на диске.

## 4. IDE

Интерфейс написан заново, без Qt. Используется `eframe`/`egui` 0.37.

Реализовано:

* меню «Файл / Правка / Программа / Вид / Исполнитель / Справка»;
* панель инструментов, горячие клавиши;
* вкладки с индикатором несохранённых изменений;
* проводник и недавние файлы;
* редактор с номерами строк, подсветкой синтаксиса, текущей строкой,
  отступами, Tab, встроенной отменой/повтором (собственный стек);
* автодополнение: ключевые слова, типы, функции, алгоритмы, глобальные
  и локальные переменные, подсказки по Ctrl+Space;
* поиск/замена с подсветкой совпадений (Ctrl+F);
* структура программы: алгоритмы, главный алгоритм, глобальные величины,
  переход по строке;
* консоль вывода с автопрокруткой, ограничением объёма и копированием;
* панель ошибок с переходом к строке;
* ввод с консоли через отдельное поле;
* запуск в фоновом потоке, остановка, пауза, шаг, Continue;
* точки останова (F9 или клик по «жёлобу» с номерами строк);
* панель исполнителя: поле Робота, Черепаха, Чертежник, загрузка и
  сохранение `.fil`, изменение размера поля, редактирование клеток,
  масштабирование колесом и перетаскивание, анимация шагов;
* проверка `@тестирование` и вывод оценки;
* тёмная/светлая тема, размер шрифта, вкл/выкл номеров строк;
* drag&drop `.kum`-файлов;
* встроенный справочник языка.

Отличия от Qt-версии:

* нет нативных диалогов ОС — используется встроенный файловый менеджер
  (плюс drag&drop и аргумент командной строки);
* панель переменных показывает снимок при паузе/шаге, но нет watch-выражений и стека вызовов;
* нет дерева курсов, редактора курсов и teacher-режима как отдельных
  приложений;
* нет иконок и анимации Qt-исполнителей — отрисовка упрощённая, но
  семантика команд сохранена.

## 5. Отладка

`runner.rs` запускает интерпретатор в отдельном потоке. `Host::on_line`
вызывается перед каждым оператором и:

* передаёт текущую строку в UI (подсветка);
* останавливается на точках останова;
* ждёт продолжения/шага при паузе;
* проверяет флаг остановки.

Поддерживается:

* `F5` — запуск, `Shift+F5` — остановка;
* `F6` — пауза/продолжить;
* `F10` — шаг;
* `F9` — точка останова на текущей строке;
* клик по номеру строки — установка/снятие точки.

При паузе и шаге IDE получает снимок локальных и глобальных переменных
(имя, тип, значение) и показывает его в правой панели. Стека вызовов и
watch-выражений пока нет; для подробностей можно использовать `вывод`.

## 6. Исполнители

Подробнее — [ACTORS.md](ACTORS.md).

* **Робот** (`actors.rs`): поле, стены (битовая маска 1/2/4/8),
  закрашивание, символы, радиация, температура, стартовая клетка;
  команды `вверх/вниз/влево/вправо`, `закрасить`, `* стена`, `* свободно`,
  `клетка закрашена/чистая`, `радиация`, `температура`;
  внутренние `@@размер поля`, `@@робот`, `@@метка`, `@@закрашена`,
  `@@верхняя/нижняя буква`, `@@температура`, `@@радиация`.
* **Черепаха**: `поднять/опустить хвост`, `вперед`, `назад`,
  `влево`, `вправо`, `выбрать чернила`; рисует отрезки.
* **Чертежник**: `опустить/поднять перо`, `выбрать чернила`,
  `сместиться в точку`, `сместиться на вектор`, `написать`.
* Поле Робота читается из `.fil` (размер, позиция, стены, цвет,
  радиация, температура, символы).

Не перенесены: Рисователь (растровый), Водолей, Кузнечик, Клавиатура,
изометрический Робот, комплексные числа. Команды этих модулей не
обрабатываются; программы с ними нужно адаптировать.

## 8. Не перенесено (осознанно)

| Компонент | Причина / что делать |
|---|---|
| Байткод `.kod` | формат — сериализация Qt-структур VM; проще пересобрать из `.kum`. CLI сообщает об этом. |
| LLVM-генератор | интерпретатор покрывает выполнение; LLVM нужен был для скорости. |
| Python-плагин | отдельный язык, не относится к КуМиру. |
| Курсы (UI) | нет дерева курсов и редактора; поддержаны `@тестирование`, оценки и `.fil`, чего достаточно для проверки задач. |
| DocBook-viewer | не влияет на выполнение программ. |
| Прочие исполнители | см. раздел 6. |
| Криптоподпись `.kum` | поле сохраняется; проверка не реализована. |
| Нативные диалоги, иконки, анимации | заменены кроссплатформенными средствами egui. |

## 9. Архитектура

```
kumir-ide (eframe)
  ├── app.rs        панели, вкладки, редактор, меню, диалоги
  ├── runner.rs     поток исполнения, пауза/шаг/точки останова, ввод
  ├── theme.rs      палитра, шрифты, стиль
  └── file_dialog.rs
        │
        ▼
kumir-core
  ├── lexer.rs ──► parser.rs ──► ast.rs
  │                              │
  ├── kumfile.rs (маркеры .kum)  ▼
  ├── builtins.rs ◄──── interpreter.rs ──► value.rs
  ├── actors.rs  ◄────┘
  └── highlight.rs (для GUI)
        │
        ▼
kumir-run (CLI)
```

Интерпретатор хранит глобальный кадр, стек вызовов, таблицу файлов,
состояние исполнителя и буферы ввода. Каждый оператор сообщает номер
строки через `Host`, что и обеспечивает отладку и подсветку.

## 10. Известные ограничения языка

* статическая проверка типов не выполняется; ошибки типов возникают во
  время выполнения (оригинал проверял на этапе компиляции);
* пользовательские записи/перечисления, кроме `файл`, не поддерживаются;
* срезы массивов как lvalue и как параметры не поддерживаются
  (срезы строк — поддерживаются);
* не всё расширение `@@`-функций исполнителей; реализованы перечисленные
  в разделе 6;
* имена, совпадающие с командами исполнителей, разрешаются в пользу
  объявленной переменной (эвристика парсера).
